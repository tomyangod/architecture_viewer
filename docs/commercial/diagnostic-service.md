## 你买到什么（四件交付物）

| 交付物 | 是什么 | 不是什么 |
|--------|--------|----------|
| **1. 扫描报告** | 全仓摸底：分层、跨层、漂移、文件级 import 环。每条 finding 带证据（文件/行号/边），可复核。 | 不是代码正确性、安全或性能审查。 |
| **2. 增量 diff** | 对照 git HEAD（或会话基线）的 Before / After：本轮新增了哪些边、删了谁、波及谁。 | 不是全量治理清单，也不把历史债伪装成本轮问题。 |
| **3. 修复优先级** | 人工把真阳性、误报、可接受债务分开，给出「先改 / 可挂账 / 可忽略」三档。 | 不是代你改代码，也不保证改完业务一定对。 |
| **4. 45 分钟讲解** | 远程走读报告：怎么读红绿、为什么这条是真的、下一次 AI 改完如何 3 秒自检。 | 不是架构咨询项目，不写组织级规范包（那是 [Team](COMMERCIAL.md) / [私有化](team-onprem.md)）。 |

交付窗口：到账后 **48 小时内**出报告与优先级；讲解按双方日历约在其后 3 个工作日内。

## 退款

**没有有效发现，全额退款。**

「有效发现」指至少一条**可复核的结构事实**：跨层串门、本轮新出现的文件级依赖环、真实漂移（代码有、图/分层没有）、本轮新增第三方包等，且能指出证据位置。下列不算有效发现，因此会退款：

- 只有历史噪音、vendored 目录误报、或分层未配置导致的「看起来很多红灯」
- 扫描失败、仓无法在约定期限内提供可运行副本
- 结论停留在「建议你们重视架构」而没有一条带证据的 finding

退款走原微信转账路径，核验后 **3 个工作日**内退回。已开票的先红字/作废发票再退。讲解已召开但仍零有效发现，同样退款。

## 诚实声明

**Architecture Viewer 是开源、Apache-2.0 的免费工具。** 你现在就可以：

```bash
npx --yes --package arch-viewer@0.12.2-rc.6 arch-viewer session report /绝对路径/to/repo --renderer builtin
```

自己出红绿灯。Community 的 extract / diff / session / MCP / 自托管 Actions **永不付费墙**，边界见 [COMMERCIAL.md](COMMERCIAL.md)。

**这次收费买的是人的时间：** 我替你跑全量+增量、剔除误报、写下修复顺序、用 45 分钟讲到你能转述给同事。工具跑出来的原始 JSON 你本来就能免费拿到。

已在真实仓上做过同类体检（约 5.7 万行量级的舆情监控仓 dogfood）：全量摸底会倒出历史债；增量门只看本轮；首轮曾把 vendored 子项目算进漂移（约 **46%** 潜在误报），排除规则落地后收口；第三方独立评估综合约 **7.0 / 10**。细节在仓库公开报告里，不在本页复述成营销故事。
