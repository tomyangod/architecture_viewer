00开工前准备（只做一次）

本工具用 Node.js ≥ 18。建议直接装全局 CLI；跟做迷你仓时还要有本仓库源码。

检查 1

打开「终端」（Terminal）

  • Mac：Command + 空格，搜「终端」回车
  • Windows：搜 PowerShell 或「命令提示符」
检查 2

看 Node 装好了没有

node -v
npm -v

应出现类似 v20.x.x 和 10.x.x。

若提示 command not found：先去 nodejs.org 下载 LTS，装完重新打开终端再试。
检查 3

安装 CLI（日常用法）

npm i -g arch-viewer
arch-viewer --version
# 应打印 0.11.x（与 npm 包版本一致）

国内若装到旧版，可显式：

npm i -g arch-viewer@0.11.2 --registry https://registry.npmjs.org
检查 4

跟做 Demo 时：进入本仓库根目录

把路径换成你电脑上的真实路径：

cd ~/Desktop/architecture_viewer
# Windows 示例：
# cd %USERPROFILE%\Desktop\architecture_viewer
ls
# 应能看到 package.json、lib、examples、docs
npm install   # 第一次必做；装过可跳过
分清两件事：日常验收用全局 arch-viewer；本页 Demo 2 用仓库里的 examples/beginner-demo/ + 脚本，所以要先 cd 到本仓库。

Demo 130 秒看六视图（只看效果）

目标：不配 API Key，用浏览器看「架构门户」长什么样。

步骤 1

启动本地网页

npm run web

看到类似 listening on http://127.0.0.1:3847 就成功了。这个窗口不要关。

步骤 2

用浏览器打开

打开什么地址你会看到
落地页 http://127.0.0.1:3847/ 产品介绍、定价入口
六视图演示（必看） …/samples/showcase/ 咖啡店示例六视图
漂移红灯演示 …/samples/drift-fail/ 故意坏图（理解「图和代码不一致会挂」）
学会没有：能在六视图页切换 Tab，找到模块名（如 api / worker）。 更短的「只看效果」清单见 MVP.md。

Demo 2 ★AI 会话架构验收（核心卖点）

这是本工具和「出一张静态架构图」的最大区别： 不是问「仓库现在长什么样」，而是问「这次 AI 改完之后，结构有没有塌」。

物料：examples/beginner-demo/。 v1 分层干净（控制器 → 服务 → 仓储）；v2 模拟 AI「多写了支付服务，控制器却直接碰仓储」。

方式 A · 一键跟做（推荐）

一条命令

在仓库根跑演示脚本

npm run demo:beginner:step
# 或：bash scripts/beginner-demo.sh

脚本会停在每一步等你按回车。最后会尝试自动打开 HTML 报告。

一口气跑完不暂停：npm run demo:beginner

方式 B · 手动四步（理解每个命令）

步骤 1

复制干净代码到临时目录

DEMO=/tmp/av-beginner-demo
rm -rf "$DEMO"
cp -R examples/beginner-demo/v1 "$DEMO"
ls "$DEMO"

应看到 controller、service、repository、domain。

步骤 2

AI 改代码之前：拍基线

arch-viewer session start "$DEMO"
# 本仓源码调试也可用：
# node lib/cli.js session start "$DEMO"
成功时大致会写 Baseline recorded … Saved to: …/graph-baseline.json
快照在 $DEMO/.av/graph-baseline.json（本地，不上传）。
步骤 3

模拟「AI 改坏了」

cp examples/beginner-demo/v2-ai-patch/service/payment_service.py "$DEMO/service/"
cp examples/beginner-demo/v2-ai-patch/controller/order_controller.py "$DEMO/controller/"
步骤 4

出报告并打开浏览器

arch-viewer session report "$DEMO" --open
你该盯住：
  • 新增类型：PaymentService
  • HIGH 层级穿透：控制器 → 仓储
  • 浏览器打开 .av/session-report.html（唯一入口）；可点「仅违规」
  • 退出码常为 1——故意的，方便以后接 CI

报告词对照

报告里写的人话
新增类型 / +types多了新的类、函数、组件
层级穿透 / layer-skip不该跨的层跨了，例如控制器直连仓储
影响面 / Impact改动了谁，还可能波及谁
Risk HIGH建议先别合并，先人工看一眼
退出码 1架构门未通过（报告已写出，不是工具崩溃）
常见翻车：不要对整个 architecture_viewer 工具仓跑 session（评测/文档噪音大）。 小白请用本 Demo 的临时目录；对自己项目时，在业务仓库根跑，并显式传绝对路径。

FAQ新手最常问

Q：我必须会 Python / Go 吗？

不用。Demo 2 用 Python 只是举例；工具也扫 JS/TS/Vue/Svelte/Java/Go。

Q：和 git diff 有什么不同？

git diff 看「改了哪些行」；本工具看「类型 / 依赖 / 分层有没有动」，专门抓跨层 import 这类结构问题。

Q：会不会上传我的代码？

会话分析默认在本地跑。网页「粘贴仓库 URL 生成」才是服务端克隆，那是另一条路径。

Q：红灯一定是错吗？

不一定。表示「值得亲眼看一眼」；你接受后刷新基线即可。见 Quickstart §9。

Q：扩展 / F5 开发主机呢？

VS Code 扩展方向暂缓。日常用 arch-viewer setup + MCP，不要再依赖 F5 扩展开发窗口。
