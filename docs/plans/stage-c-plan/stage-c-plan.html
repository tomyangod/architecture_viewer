关键实现决策

  • 默认 spawn CLI，不在扩展宿主里 require tree-sitter：tree-sitter 是 native addon，Electron 扩展宿主的 ABI 与本机 Node 经常不一致。W8 第一天用 child_process.spawn('npx', ['arch-viewer', 'session', 'report'])（或捆绑的 bin/arch-viewer.js）作为主路径；若某环境验证直连 require 稳定，再作为可选加速。
  • 防抖用 setTimeout：FileSystemWatcher 触发后重置 30s 定时器，到期后 spawn CLI。提取过程约 1–3s（中小仓库），用 Progress 显示。
  • Webview 而非浏览器：session-report.html 是自包含的，直接作为 Webview HTML 内容注入，无需本地 HTTP 服务。
  • 状态栏优先于通知：通知容易被忽略且打断，状态栏角标是持续可见但不打断的平衡点。
  • 不碰 Cursor 私有 API：文件监听是编辑器无关的，Cursor / Trae / Windsurf 写的文件都能被 VS Code 扩展捕获（只要工作区在 VS Code 中打开）。
与现有六视图命令的关系：会话模式是新命令，不改动现有 Init/Generate/Validate/Preview。两套功能共存——六视图是存量理解（仓库长什么样），会话报告是增量验收（AI 改了什么）。用户可以只用会话模式，也可以两者都用。

04交付物 2：GitHub Action — PR 架构评论

现有 templates/architecture-check.yml 做的是六视图漂移检查（架构图是否过期），面向的是已接入 kit 的仓库。阶段 C 需要一个新 Action：在 PR 中自动评论「本 PR 在架构层面改变了什么」，面向的是任何仓库（无需预先接入 kit）。

两种 Action 的定位差异

维度architecture-check.yml（已有）architecture-diff.yml（阶段 C 新建）
面向已接入六视图 kit 的仓库任何仓库，零配置
检查什么架构图是否过期 / 是否有占位符PR 在架构层面改变了什么
输出Pass / Fail（exit code）PR 评论（架构变更清单 + 风险标记）
数据源kit 目录的 Mermaid 图 vs 代码扫描base ref vs head ref 的 graph.json diff
门槛坏图红灯（CI 必须失败）评论信息（默认不 block，可选 block 高风险）

关键实现决策

  • 零配置可用：用户只需把 yml 放进 .github/workflows/，无需 av init 或 kit 目录。Action 自己在 base/head 上跑提取。
  • 评论更新而非追加：每次 push 新 commit 时更新已有评论，而非创建新评论——避免 PR 被刷屏。
  • 默认不 block：评论是信息性的，不设 action 为 must-pass。可选 fail-on-high-risk: true 让高风险 PR 阻断合并。
  • SVG 内联：评论中的架构图用 SVG（GitHub 支持），而非外链图片——离线可看、不依赖图片托管。
  • base ref 取 PR base SHA：而非 main 分支最新——确保 diff 只反映本 PR 的变更，不混入 main 的新提交。

08风险与对策

风险等级对策
