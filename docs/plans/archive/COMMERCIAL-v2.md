## 一、先把两件事分开

Archify 值得学的是**分发与信任**，不是它的**赚钱方式**。

| | Archify（已核实） | 本项目应当坚持 |
|---|---|---|
| 产品 | Agent 对话里产出可校验的精美图 | AI 改完代码后拦住坏结构 |
| License | MIT，Skill 整包可拷 | Community 继续 Apache 2.0（已对外发布） |
| 收入 | README 赞助位：APINEBULA **联盟链接 + 9 折码**；EverMind **品牌露出 + Skill 互嵌**；公开征赞助邮箱 | **订阅 + 托管自动化**为主；赞助/联盟是辅线 |
| 护城河 | 渲染、交互、delivery contract | 多语言提取、风险规则、影响面、会话基线 |
| 用户付费理由 | 几乎没有（图免费） | 团队不想自己养 Action / 告警 / 多仓看板 |

Archify 没有 Pro 价目表。它用装机量和 README 货架换钱。你的单客价值更高，**不要为了「学 Archify」改成只靠赞助**。

v1（`COMMERCIAL.md`）另一处过时：收费理由还停在「六视图门户 / Generate / Mermaid」。真实产品已经是 **session report + 风险 + 影响面 + MCP**。对外叙事必须先改这一句，否则定价表怎么调都对不上买家。

## 二、优化后定位

**Architecture Viewer = AI 编码时代的架构验收门。**  
图是报告的呈现（内置 SVG，或导出给 Archify）。买家买的是：**本轮改了什么、有没有跨层、波及谁、要不要拦。**

和别人怎么错开：

| 产品 | 他们卖什么 | 你不跟他们抢 |
|---|---|---|
| Archify / Mermaid | 图画得清楚、能演示 | 上下游：你出事实 IR，它们出图 |
| Sonar / Codacy | 代码坏味道、覆盖率 | 你查的是层、依赖方向、本轮结构差 |
| Sourcegraph | 搜代码、大仓导航 | 你绑定「这一次 AI 会话 / 这一次 PR」 |
| **Import Linter / dependency-cruiser** | 语言级 import 硬规则、CI 违规 | **互补不竞争**：它们管「规则是否被违反」，你管「本轮 AI 改了什么、影响谁」；README 主动推荐组合使用 |
| **Sonargraph / CodeScene** | 企业级全量架构治理、热点、质量门 | 它们是「正式架构治理平台」（重、贵、学习成本高）；你是「AI 改码后的轻量增量验收门」，成本约 1/10，5 分钟装好 |

一句话：Sonar 问代码写得好不好；你问**架构还对不对**。

> 2026-09 第三方实测结论（见 `docs/` 评测记录）：独立评测在真实仓跑完全链路后，最终推荐架构正是「Import Linter（Python 硬规则）+ dependency-cruiser（JS 硬规则）+ Architecture Viewer（本轮增量可视化）」。大方承认分工、主动推荐组合，比假装全能更能建立专业信任。

### 三个产品的明确分工

不要试图在一个工具里做所有事。分工越明确，用户越知道什么时候该选你：

| 层级 | 工具 | 负责什么 | Architecture Viewer 的关系 |
|---|---|---|---|
| **AI 会话验收门** | Architecture Viewer | 基线、增量 diff、Before/Delta/After、本轮新增风险、影响面、MCP 低摩擦体验 | **本体**——只做增量时刻的结构变化感知 |
| **语言级硬规则** | Import Linter（Python）、dependency-cruiser（JS/TS） | 明确可重复的依赖契约、CI 硬阻断、循环依赖、模块黑白名单、层级规则、高精度语言生态解析 | **互补，不竞争**——通过可插拔分析器接入，增强 AV 的数据精度；用户也可单独使用 |
| **企业级架构治理** | Sonargraph、CodeScene | 全量治理、Git 历史热点、组织/所有权、多仓分析、质量门、趋势和审计 | **重型替代**——团队长大、需要正式治理流程时迁移过去，AV 是轻量入口 |

### 可插拔分析器策略（W16-03）

不是「接 dep-cruiser 替换内置解析器」，而是「内置保底 + 检测到外部工具时自动增强」：

```
内置分析器（零依赖、永远可用）
   ↓  统一中间格式：nodes / edges / violations / evidence / sourceAnalyzer / confidence
Import Linter 适配器（检测到 .importlinter 配置时启用，增强 Python）
   ↓
dependency-cruiser 适配器（检测到 .dependency-cruiser.js 时启用，增强 JS/TS）
```

理由：
- 开箱即用是产品底线——不能让用户先装一堆东西才能看报告
- 两个工具输出模型不同，需要统一到 AV 的中间格式才能进 diff 引擎和图渲染
- 外部工具升级可能改变输出，适配器层做版本兼容，核心引擎不受波及
- 用户可以先用内置跑通，再按需装增强工具，渐进式提升精度
- 免费层用内置，Pro/Team 层支持增强适配器——这是质量升级，不是功能付费墙

## 三、收费切在「自动化」，不切在「判断」

v1 的问题：Community 已经能本地跑完核心路径，Pro 只剩「托管 PR 评论」，像锦上添花。

重划原则：**分析能力永远免费；省人工、上云、进团队工作流才收费。**

| 能力 | Community | Pro | Team |
|---|---|---|---|
| extract / diff / session report / 风险 / 影响面 | 本地免费 | 同左 | 同左 |
| MCP：`av_session_*` / `av_check_layering` / `av_explain_finding` | 免费 | 同左 | 同左 |
| 自托管 Action 模板（自己跑 runner） | 免费 | — | — |
| 导出 Archify IR（`export-archify`） | 免费 | 同左 | 同左 |
| **托管 PR 评论**（不用自己养 Action） | — | 第一付费点 | 含 |
| **本机文件夹看守 + 飞书/企微告警** | — | 第二付费点 | 含 |
| **多仓聚合工作台** | — | 第三付费点 | 含 + 组织规范 |
| SSO / 审计 / 共享图库 / 私有化 | — | — | 专属 |

不卡次数、不卡语言、不卡仓库体积。  
**增量扫描保持免费**：那是分析能力，不是托管。大仓变慢用技术优化，不要做成付费墙（v2 初稿把增量放进 Pro，这里收回）。

## 五、多元收入：学 Archify 的货架，不学它当主业

### 5.1 赞助位（W04 就能挂，零产品开发）

Archify 已验证：README 一张表 = 联盟 + 品牌。

你可以挂、且不丢人的：

- 你自己在用的 AI 工具 / API 聚合（**必须真实在用**，带 ref）。
- 愿意互嵌 Skill/MCP 的 Agent 运行时（对标 EverMind × Raven）。

不要先堆阿里云/Vercel 通用云链接——和「架构门」场景远，像广告。

赞助页加一行邮箱即可。预期占收入 **<10%**，主要换曝光和「像正经开源项目」。

### 5.2 咨询（被动，高客单）

- 架构健康度诊断：**¥4999 / 次**（工具全量跑 + 10 页人工结论）。
- 分层 / `architecture-rules` 定制：**¥9999 起**。

README 放联系方式，不主动电销。有一单做一单。

### 5.3 12 个月收入结构（副业、验证用）

| 来源 | 占比 | 备注 |
|---|---|---|
| Pro / Team 订阅 | 70% | 仍是主业 |
| 咨询 | 20% | 有单再扩 |
| 赞助 / 联盟 | 10% | 学 Archify 的货架 |

## 六、License：不要把已发布的 Apache 整仓改成 GPL

v2 初稿建议 Apache → GPL 3.0 + 商业双许可。**现在改整仓风险大于收益：**

- 0.8+ 已经按 Apache 发出去，下游可以继续按旧许可使用已发布版本。
- 企业买家更认 Apache/MIT；GPL 会吓跑「想嵌进内部平台」的 Team 线索。
- 分析引擎越开放，会话门越容易被装、被引用、被写成教程——这是获客。

建议：

1. **`lib/` 提取 / diff / 风险 / 影响面 / MCP：维持 Apache 2.0。**
2. **托管与账号（`web/lib/pro/`、未来 `account/`、SaaS API）：单独商业许可或源码可见、不可对外再分发。** 新文件新许可，不回溯整仓。
3. 商标条款保留（衍生作品改名），这比换 GPL 更能挡住「换皮上架 Marketplace」。

若以后真要双许可，只对**新写的托管代码**加商业条款，并先咨询律师。W03 用 2 小时改 LICENSE 文件本身，优先级应低于改定位文案。

## 七、获客（Archify 可直接抄的三招）

1. **Agent 先于官网**：`npx` / MCP / Skill 路径。Archify 的主安装是 `npx skills add`；你的对等物是 `arch-viewer setup` + MCP。买家第一眼应在 Chat 里看到红灯，而不是落地页六视图。
2. **Proof，不是 mock**：Archify 用真实 HTML 产物当 README 图。你用真实 `session-report.html` / PR 评论截图 / 舆情仓前后分层对比。
3. **内容只写一件事**：「AI 改了一周，结构偏了没有。」不要再写「如何画 C4」。

渠道：Marketplace / npm / MCP / Gitee + 掘金/V2EX 一篇实验文。反馈表继续用 `docs/ops/feedback-tracking.md`。

与 Archify 互推放到 **IR 适配器在真实仓上跑通 compare 之后**（见集成方案 Phase 3），空口合作没有说服力。

## 八、指标

- **上架期（W03–W06）**：安装 500+；会话门被外人用过的证据 ≥5 条（截图/issue）；Pro 试用 50+。
- **转化期（W07–W12）**：付费转化 3–5%；至少 1 笔 Team 或咨询。
- **护栏**：核心分析不进付费墙；默认代码不上云；每周投入 ≤20h。

北极星仍是「有人付钱是因为不想自己养门禁」，不是 star 数。

## 十、和集成方案的关系

渲染交给 Archify（或继续内置 fallback）**不削弱收费点**。Archify 的 compare 自己写了：只对 authored IR 做结构差，不推断风险。风险、影响面、会话门仍是你的产品。导出 IR 应留在 Community，用来借 Archify 的用户看见「这图是从代码追出来的」。
