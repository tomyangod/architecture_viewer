# 架构验收门：小白使用指南（0.10.0）

> **你只需要知道一件事**：让 AI 改代码后，这个工具帮你检查**项目结构有没有被改坏**。

## 这个工具是干什么的？（30 秒看懂）

你的项目好比一栋大楼，AI 是装修工人。装修前拍张照片，装修后再拍一张，两张一对比——动了哪里、有没有拆承重墙，一目了然。

```
  改之前拍照片          AI 改代码           改之后对比
 ┌──────────┐      ┌──────────┐      ┌──────────┐
 │  📷 咔！  │  →   │ 🔨 敲敲打打 │  →   │  📋 变化  │
 │          │      │          │      │  清单出炉  │
 │ 记下大楼 │      │  改了几个  │      │ 哪里新增了 │
 │ 当前样子 │      │  房间/走廊  │      │ 哪里拆了  │
 └──────────┘      └──────────┘      │ 有没有串门  │
                                     └──────────┘
```

**红绿灯**：绿灯 = 结构没改坏，可以继续。红灯 = 有地方可能改坏了，你需要亲眼看一下。

## 核心概念图解（看不懂术语？看这里）

### 你的项目 = 一栋大楼

```
┌──────────────────────────────────┐
│  🏢 前台层（接收用户请求）          │  ← 网页、API入口
│  ┌─────┐  ┌─────┐  ┌─────┐      │
│  │房间A │  │房间B │  │房间C │      │  每个文件 = 一个房间
│  └──┬──┘  └─────┘  └─────┘      │
│     │ 走廊                        │  文件之间的引用 = 走廊
├─────┼────────────────────────────┤
│  🏪 中间层（处理业务逻辑）          │
│  ┌─────┐  ┌─────┐                │
│  │房间D │  │房间E │                │
│  └──┬──┘  └─────┘                │
│     │                            │
├─────┼────────────────────────────┤
│  📦 仓库层（存数据）               │  ← 数据库相关
│  ┌─────┐                        │
│  │房间F │                        │
│  └─────┘                        │
└──────────────────────────────────┘
```

**重要规则**：前台不该直接跑去仓库拿东西——要经过中间层。直接串门 = 红灯。

### 术语对照表（遇到看不懂的词，查这里）

| 你会看到的词 | 大白话意思 | 大楼比喻 |
|-------------|-----------|---------|
| 基线 / 快照 | 改之前的结构记录 | 装修前拍的照片 |
| 指纹 | 结构的唯一编号 | 照片的条形码，变了 = 结构变了 |
| 分层 | 把文件分到不同楼层 | 一楼前台、二楼办公、地下室仓库 |
| 分层覆盖率 | 多少文件已分到楼层 | 大楼里多少房间挂了楼层牌 |
| 跨层违规 / 层级穿透 | 不该跨层引用的地方跨了 | 前台直接跳进地下室，不走楼梯 |
| 实体 / 类型 | 类、函数、组件等 | 房间里的家具 |
| 外部依赖 | 从外面引入的包 | 外购的家具 |
| 扇出 | 一个文件引用了太多其他文件 | 一个房间开了太多门 |
| 影响面 | 改一处会波及哪些地方 | 改了一个房间，哪些房间会受影响 |
| diff | 前后对比的变化清单 | 装修前后对比单 |
| MCP | 让 AI 助手自动帮你检查 | 不用你自己跑，管家自动看 |
| Agent | AI 助手（Cursor / Claude 等） | 帮你干活的管家 |
| 退出码 1 | 工具发现有红灯 | 体检报告亮红灯 |

## 两种用法（选一种就好）

| 用法 | 你做什么 | 适合谁 |
|------|---------|-------|
| **A. 自己敲命令**（第 1–3 节） | 改前敲一条命令，改后敲一条命令 | 想自己掌控节奏的人 |
| **B. 让 AI 自动检查**（第 7 节，推荐） | 配置一次，之后 AI 自动拍照、自动检查 | 用 Cursor / Claude 的人 |

两种方式同一个引擎，检查结果完全一样。

## 0. 准备（只做一次）

```bash
cd ~/Desktop/architecture_viewer
npm install          # 装过可跳过
```

设两个变量方便复制（路径按你的实际情况改）：

```bash
export AV="$HOME/Desktop/architecture_viewer"
export REPO="$HOME/Desktop/publicopinionmonitor_v2"
```

## 1. 改代码之前：拍一张"改之前"的照片

```bash
node "$AV/lib/cli.js" session start "$REPO"
```

**你会看到：**

```
Baseline recorded: 246 files, 1543 types
Fingerprint: 540d963c8c014084
Saved to: <你的项目>/.av/graph-baseline.json
Layer suggestions: <你的项目>/.av/layers.suggested.json
```

**翻译成人话：**

| 输出 | 意思 |
|------|------|
| 246 files, 1543 types | 你的项目有 246 个文件、1543 个组件 |
| Fingerprint | 这张"照片"的条形码，变了就说明结构改了 |
| Saved to | 照片存在你项目的 `.av` 文件夹里，不上传云端 |
| Layer suggestions | 工具自动帮你分好了楼层，不用你配 |

**关于自动分楼层**：工具会看每个文件里用了什么框架、文件夹叫什么名字，自动判断它属于前台层、中间层还是仓库层。你什么都不用做。觉得分错了才需要手动改（见第 4 节）。

## 2. 日常三步（养成习惯）

```bash
# ① 改代码之前：拍照片
node "$AV/lib/cli.js" session start "$REPO"

# ② AI 改完之后：看对比报告
node "$AV/lib/cli.js" session report "$REPO" --open

# ③ 报告里的变化你认可后：拍新照片，开始下一轮
node "$AV/lib/cli.js" session start "$REPO"
```

`--open` 会用浏览器打开报告，点「仅变更」只看这次改了什么。

**刚拍完照片立刻看报告，大概率是绿灯（无变更）**——说明结构没动，正常。

### 报告里重点看三块

```
┌─────────────────────────────────────────┐
│  ① 变化汇总                               │
│  +新增 3  -删除 1  ~修改 2               │
│  （多了3个组件、删了1个、改了2个）           │
├─────────────────────────────────────────┤
│  ② 红绿灯                                 │
│  🔴 红灯：必须看（可能改坏了）              │
│  🟠 黄灯：建议看（有点担心）               │
│  🔵 蓝灯：随便看（小问题）                 │
│  ✅ 绿灯：没问题                           │
├─────────────────────────────────────────┤
│  ③ 波及范围                               │
│  改了房间A → 房间B、房间C 会受影响         │
│  （改一处会不会牵动一片）                   │
└─────────────────────────────────────────┘
```

## 3. 演示：故意"串门"，看看红灯长什么样

> 这一步在临时副本里做，**不碰你桌面上的真实项目**。

```bash
# 复制一份到临时目录
rm -rf /tmp/pom-av-demo
rsync -a --exclude='.venv' --exclude='node_modules' --exclude='__pycache__' \
      --exclude='logs' --exclude='.av' --exclude='*.log' \
      "$REPO"/ /tmp/pom-av-demo/

# 给副本拍照片
node "$AV/lib/cli.js" session start /tmp/pom-av-demo

# 模拟 AI 犯的典型错误：前台直接跑去仓库拿东西
printf '\nfrom database.db_session import get_async_engine\n' \
  >> /tmp/pom-av-demo/backend/routes/alerts.py

# 看报告
node "$AV/lib/cli.js" session report /tmp/pom-av-demo --open
```

**你会看到红灯：**

```
--- 新增走廊 ---
  + alerts.py ──引用──> db_session.py

--- 红灯 ---
  🔴 串门了：前台直接跑到仓库，跳过了中间层
     alerts.py → db_session.py

Risk level: HIGH (1 个红灯)
```

**翻译成人话**：

```
  前台层              中间层              仓库层
┌──────┐           ┌──────┐          ┌──────┐
│alerts│ ──红色箭头────────────────→ │db_   │
│.py   │   ❌ 串门！跳过了中间层！      │session│
└──────┘           └──────┘          └──────┘
                   应该走这里 ↗
```

工具发现 `alerts.py`（前台层）直接引用了 `db_session.py`（仓库层），跳过了中间层——这就是"串门"，亮红灯。正确做法是让前台调用中间层，中间层再去仓库。

## 4. 万一楼层分错了怎么办（少见，但要知道）

绝大多数项目不用管。如果某个文件夹被分到了错误的楼层：

1. 打开 `<你的项目>/.av/layers.suggested.json`，找到那个文件夹
2. 复制一份为 `<你的项目>/.av/layers.json`，改成你要的楼层：

```json
{
  "mydata": "storage",
  "helpers": "util"
}
```

3. 重新拍照片（`session start`）。你的 `layers.json` 优先级最高，工具不会覆盖它。

> **简单记**：`layers.suggested.json` 是工具的**建议**（可随时重新生成），`layers.json` 是你的**决定**（写了就锁定）。

## 5. 哪些文件该提交到 Git

在你的项目 `.gitignore` 里加：

```gitignore
.av/session-report.*
```

| 文件 | 提交？ | 原因 |
|------|-------|------|
| `graph-baseline.json` | **提交** | 团队共享同一张"改前照片" |
| `layers.json` | **提交** | 团队共享楼层规则 |
| `session-report.*` | 不提交 | 本地报告，各人生成 |
| `layers.suggested.json` | 不提交 | 工具自动生成 |

## 7. 让 AI 自动帮你检查（推荐！配一次就不用敲命令了）

从 0.10.0 起，你可以让 AI 助手（Cursor / Claude / DeepSeek Harness）**自动**在改代码前拍照片、改完后自动检查。你配置一次，之后只管跟 AI 对话就行。

### 7.1 自己敲命令 vs 让 AI 自动检查

| | 自己敲命令（第 2 节） | 让 AI 自动检查（本节） |
|---|---|---|
| 谁拍照片 | 你敲命令 | AI 改代码前自动拍 |
| 谁检查 | 你敲命令 | AI 改完自动查 |
| 你要做什么 | 记住三步、敲三条命令 | 配置一次，之后正常对话 |
| 发现红灯怎么办 | 你自己看报告 | AI 自动解释 + 给修复建议 |

### 7.2 AI 手里有 5 个"检查工具"

| 工具 | AI 什么时候用 | 做什么 |
|------|-------------|------|
| `av_session_start` | 改代码**之前** | 拍"改之前"的照片，**并开启自动监听** |
| `av_session_changes` | 改完代码、回复你**之前** | 轻量检查"有没有架构变更"（秒回、不生成文件） |
| `av_session_report` | `changes` 报有变更时 | 看完整报告（Before/After 对比图 + 风险红灯）；自动监听已生成则秒回 |
| `av_check_layering` | 第一次摸底时 | 把全楼所有"串门"查一遍（**历史老问题**） |
| `av_explain_finding` | 遇到红灯时 | 解释谁串了谁的门、怎么修 |

> **自动闭环**：`av_session_start` 后系统会自动监听文件变化。AI 改代码时不断保存，系统在 AI **停下 20 秒后自动生成架构报告**，不需要 AI 手动触发。AI 改完代码后调 `av_session_changes` 轻量确认，有变更再调 `av_session_report` 看详情（缓存命中秒回）。

> **两个检查工具别混用**（重要）：
>
> - `av_session_report` 只看**这次改动**有没有引入新问题——日常用它，不会被历史代码干扰。
> - `av_check_layering` 查**全楼所有问题**。比如你的项目可能有 200 多条历史"串门"，那是以前积累的老问题，不是你这次改出来的。适合第一次摸底，不适合每次验收。

### 7.3 一键安装（最省事，推荐）

在终端跑一条命令，工具会自动找到你电脑上的 Cursor / Claude，自动写好配置、自动备份原文件：

```bash
cd ~/Desktop/architecture_viewer
node lib/cli.js setup
```

跑完会自动打开一张图文引导页，告诉你接下来只需要：**重启 AI 工具 → 打开项目 → 说一句"改代码前先拍照片，改完检查有没有改坏"**。

> 不想用一键安装？下面是手动方式（效果一样）。

### 7.4 手动接入 Cursor

编辑 `~/.cursor/mcp.json`，加一段：

```json
{
  "mcpServers": {
    "arch-viewer": {
      "command": "node",
      "args": [
        "/Users/你的名字/Desktop/architecture_viewer/mcp/server.js"
      ]
    }
  }
}
```

然后：

1. 完全退出并重新打开 Cursor
2. 打开你的项目文件夹
3. 新开 AI 对话，问一句：**「列出你可用的 MCP 工具，有没有 arch-viewer？」**

应能看到 5 个工具。

### 7.5 接入后怎么用（你只需要说人话）

配置好后，正常给 AI 派活就行：

> 「帮我给 alerts 加一个导出功能。改之前先用 arch-viewer 拍照片，改完检查有没有串门。」

AI 会自己：拍照片 → 改代码 → 检查 → 如果有红灯，解释谁串了门、怎么修 → 用大白话告诉你。

**这就是让 AI 自动检查的核心好处**：你不需要知道"照片""楼层""串门"这些概念，也不用在改代码和检查之间切换——检查变成了 AI 工作流里自动的一步。

### 7.6 命令行确认 AI 工具能用（可选）

不用 Cursor 也能确认工具正常：

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' \
  | node "$AV/mcp/server.js"
```

能打印出 5 个工具的信息就成功了。

## 8. 常见问题

**Q：报告显示"无变更"，但我明明改了代码？**

你改的是函数内部实现、注释、配置值——结构（文件/组件/引用关系）没变，所以不报。这是对的：结构没变就不打扰你。

**Q：红灯一定是错吗？**

不一定。红灯表示"这里有一个值得你亲眼看一下的变化"。有时前台直连仓库是有意为之，你确认合理后，拍新照片即可——工具负责**让你看见**，判断权在你。

**Q：检查会不会很慢 / 要联网 / 要密码？**

246 个文件约 1～2 秒查完；完全离线、不需要任何密码。

**Q：第一次想练手，怕搞坏真实项目？**

先用第 3 节的临时副本练，跑顺了再对真实项目用。

**Q：全楼查出 200 多条红灯，吓死人？**

你用错工具了——`av_check_layering` 查的是全部历史问题。日常验收用 `av_session_report`，只看这次改了什么。第一次摸底才用 `av_check_layering`。
