00开工前准备（只做一次）

本工具用 Node.js 跑。电脑需要先装好 Node（建议 18 或更高）。

检查 1

打开「终端」（Terminal）

  • Mac：按 Command + 空格，搜「终端」或 Terminal，回车
  • Windows：搜 PowerShell 或「命令提示符」
检查 2

看 Node 装好了没有

node -v
npm -v

两行都输，每行回车。应出现类似 v20.x.x 和 10.x.x。

若提示「不是内部或外部命令」/ command not found：先去 nodejs.org 下载 LTS 安装包，装完重新打开终端再试。
检查 3

进入本项目文件夹

把下面路径换成你电脑上的真实路径（把仓库放在桌面时大致如下）：

cd ~/Desktop/architecture_viewer
# Windows 示例：
# cd %USERPROFILE%\Desktop\architecture_viewer

确认进对了：

ls
# 应能看到 package.json、lib、examples、docs 等
检查 4

安装依赖（第一次必做）

npm install

等它跑完，没有红色大片报错即可。以后一般不用再装。

小窍门：下面所有命令默认你已经在仓库根目录（有 package.json 的那一层）。 若报「找不到文件」，多半是 cd 错了目录。

Demo 130 秒看六视图（只看效果）

目标：不装扩展、不配 API Key，用浏览器看「架构门户」长什么样。

步骤 1

启动本地网页

npm run web

看到类似 listening on http://127.0.0.1:3847 就成功了。这个窗口不要关，关掉服务就停了。

步骤 2

用浏览器打开

打开什么地址你会看到
落地页 http://127.0.0.1:3847/ 产品介绍入口
六视图演示（必看） http://127.0.0.1:3847/samples/showcase/ 咖啡店示例的 Context / Container / … 六张图
漂移红灯演示 http://127.0.0.1:3847/samples/drift-fail/ 故意坏掉的图（用来理解「图和代码不一致会挂」）
验收自己学会了没有：能在六视图页切换 Tab，找到模块名（比如 api / worker）。 觉得「图还行」→ 继续 Demo 2；觉得「只要看图」→ 也可以先停在这里。

Demo 2 ★AI 会话架构验收（核心卖点）

这是本工具和「出一张静态架构图」的最大区别： 不是问「仓库现在长什么样」，而是问「这次 AI 改完之后，结构有没有塌」。

我们准备了一个迷你订单系统：examples/beginner-demo/。 v1 分层干净；v2 模拟 AI「多写了一个支付服务，但控制器直接去碰数据库仓储」。

方式 A · 一键跟做（推荐小白）

一条命令

跑演示脚本

bash scripts/beginner-demo.sh

脚本会停在每一步等你按回车，并解释在干什么。最后会尝试自动打开 HTML 报告。

想一口气跑完不暂停：AV_DEMO_NOPAUSE=1 bash scripts/beginner-demo.sh

方式 B · 手动四步（理解每个命令）

步骤 1

复制一份干净代码到临时目录

DEMO=/tmp/av-beginner-demo
rm -rf "$DEMO"
cp -R examples/beginner-demo/v1 "$DEMO"
ls "$DEMO"

应看到 controller、service、repository、domain 四个文件夹。

步骤 2

AI 改代码之前：拍基线

node lib/cli.js session start "$DEMO"
成功时终端大致会写：Baseline recorded … Saved to: …/graph-baseline.json
这张快照存在 $DEMO/.av/graph-baseline.json，表示「改之前的结构」。
步骤 3

模拟「AI 改坏了」

cp examples/beginner-demo/v2-ai-patch/service/payment_service.py "$DEMO/service/"
cp examples/beginner-demo/v2-ai-patch/controller/order_controller.py "$DEMO/controller/"

真实生活中这一步 = Cursor / Copilot / 同学把一堆文件改完了。这里用复制补丁代替。

步骤 4

出报告并打开浏览器

node lib/cli.js session report "$DEMO" --open
你该盯住这些信号：
  • 终端里有 PaymentService 之类「新增类型」
  • 出现 HIGH / 层级穿透：OrderController → OrderRepository
  • 浏览器打开 .av/session-report.html：默认「仅变更」；可点「仅违规」
  • 退出码经常是 1（高风险）——这是故意的，方便以后接 CI

报告看不懂？对照这张表

报告里写的人话
新增类型 / +types多了新的类、函数、组件
删除类型原来的类型没了（可能是重命名未归并，或真删了）
层级穿透 / Layer skip下层不该直接依赖上层，例如控制器直连仓储
外部依赖新引入了 npm/pip 包等
影响面 / Impact改动了谁，还可能波及谁（下游模块）
Risk level HIGH建议先别合并 / 先人工看一眼
常见翻车：在仓库根目录对「整个 architecture_viewer」跑 session，会扫到很多评测/文档噪音。 小白请先用本 Demo 的临时目录；对自己项目时，在业务仓库根跑，并确保不需要的大目录在 .gitignore 里。

Demo 3给项目生成六视图

目标：把「现在仓库长什么样」写成可分享的六视图套件（和 Demo 2 的「这次改了什么」互补）。

步骤 1

在演示商店项目上生成

node lib/cli.js init examples/showcase-shop
node lib/cli.js generate examples/showcase-shop

会在 examples/showcase-shop/architecture_viewer/ 写出 6 个 .md 图 + HTML 门户。

步骤 2

本地打开门户（注意：不要用 file:// 硬开）

cd examples/showcase-shop/architecture_viewer
python3 -m http.server 8080
# 浏览器打开 http://127.0.0.1:8080/architecture_visualized.html
直接双击 HTML（file://）时，浏览器常会拦 fetch 读 .md，图是空的。用上面的小 HTTP 服务即可。
可选

校验「图有没有和代码对不上」

cd ../../..   # 回到仓库根
node lib/cli.js check examples/showcase-shop/architecture_viewer \
  --filled --drift --repo examples/showcase-shop

故意坏图夹具（应失败）：

node lib/cli.js check eval/demo-drift --filled
# 期望：退出码不是 0

Demo 4在 Cursor / VS Code 里用会话模式

目标：不用每次手敲 CLI——改完代码后状态栏角标提醒，一点就开报告。

当前扩展已实现会话命令；若尚未发布到 Marketplace，请用「扩展开发主机」本地跑（作者/贡献者常用路径）。
步骤 1

用 Cursor 或 VS Code 打开本仓库

菜单：文件 → 打开文件夹 → 选中 architecture_viewer。

步骤 2

启动扩展开发窗口

  1. 按 F5（或运行和调试里选扩展）
  2. 会弹出一个新的「Extension Development Host」窗口
  3. 在新窗口里再打开一个项目（可用 examples/beginner-demo/v1，或任意业务仓）
步骤 3

命令面板（Mac：Cmd+Shift+P / Win：Ctrl+Shift+P）

命令干什么
Architecture Viewer: Session Start记录基线（等价 CLI session start）
然后用 AI / 自己改代码停手约 30 秒后自动分析（防抖可配）
状态栏出现 AV +n …点击打开 Webview 报告
Architecture Viewer: Session Report立刻生成并打开报告
Architecture Viewer: Session Refresh不等防抖，马上重算
配置（可选）

设置里搜 architectureViewer.session

  • enabled：是否自动监听
  • debounceSeconds：默认 30，AI 狂写文件时别改太小
  • analyzeOnOpen：打开工作区时是否自动刷一次角标

日常你自己项目里怎么用（抄这段就行）

# 每次让 AI 开干之前
node lib/cli.js session start .

# …… AI / 同事改了一堆代码 ……

# 验收
node lib/cli.js session report . --open

# 觉得变更 OK，刷新基线开启下一轮
node lib/cli.js session start .

若在本仓库开发，也可以：

npm run arch:baseline    # = session start .
npm run arch:report      # = session report . --open
npm run arch:report:text # 只要终端摘要
还想看影响面「波及谁」：见 docs/IMPACT-REPORT.md， 命令形如 node lib/cli.js impact <旧目录> <新目录> --open。

FAQ新手最常问

Q：我必须会 Python / Go 吗？

不用。Demo 2 用 Python 只是举例；工具也扫 JS/TS/Vue/Svelte/Java/Go。

Q：报告里一堆函数名，看不过来？

HTML 默认「仅变更」；再点「仅违规」。终端不要加 --all（那是给排障用的全量）。

Q：和 git diff 有什么不同？

git diff 看「改了哪些行」；本工具看「类型 / 依赖 / 分层有没有动」，专门抓「多了一个跨层 import」这类结构问题。

Q：会不会上传我的代码？

会话分析默认在本地跑。网页「粘贴仓库 URL 生成」才是服务端克隆，那是另一条路径，见落地页说明。

演示物料：examples/beginner-demo/ · 脚本：scripts/beginner-demo.sh · 产品仓库根目录打开本页效果最佳。

更短的「只看效果」清单见仓库根目录 MVP.md。
