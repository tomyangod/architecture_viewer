## 1. 招募对象与筛选

- 优先 Python、JS/TS 仓库，有明确模块边界、真实 PR 流程且日常使用 AI 改码。
- 由维护者确认最近一次跨层依赖、影响面遗漏或架构 review 耗时的具体经历。仅对图好看感兴趣，不作为付费验证主样本。
- 询问现有 CI/审查工具；有自动化规则的 A 组与仅人工 review 的 B 组分别记录。
- 愿意看真实报告、每周反馈约 15 分钟，并在试用结束评估是否自费保留托管。
- 不要求公开私有代码或向作者提供 PAT。不能允许服务端 clone 的团队先走本地免费路径，并标记不是托管付费主样本。

## 2. 首次接入（先 2 个团队）

固定版本为 **0.12.2-rc.6**（已发布到 npm `next`；registry 安装已复验）。接入时钉此版本，不用 `latest`。

1. 记录团队匿名 ID、接入日期、语言、版本、现有工具和首个真实 PR；由维护者决定可分享哪些脱敏数据。
2. 在真实仓运行前检查工作区及分层规则，声明 vendored 目录。选定 git HEAD（本地）/PR base（托管）对照方式。
3. 发布后可使用固定 CLI，不先运行会写全局配置的 setup：

```bash
npx --yes --package arch-viewer@0.12.2-rc.6 arch-viewer --version
npx --yes --package arch-viewer@0.12.2-rc.6 arch-viewer session report /absolute/path/to/repo --renderer builtin
```

有有效 Git HEAD 的仓库无需 `session start`。非 Git 仓只有在客户确认记录当前状态后才建快照。exit 1 表示结构门未通过，不是安装失败；2 为参数/配置、3 为扫描、4 为基线问题。

4. 在临时分支演示一条客户认可的跨层变更，查看红灯，再撤销该演示改动查看绿灯；不提交演示错误、不刷新基线来消红灯。
5. 先作为旁路评论/参考报告，不把所有 HIGH 立即设为生产强制阻断。客户确认真正阻断规则后再启用 CI gate。
6. 需要 MCP 的团队自行确认 setup 将修改的配置；需要托管的团队按 [PRO-SAAS](../../docs/commercial/PRO-SAAS.md) 自行配置凭据并完成真实 PR 验收。
7. 记录实际接入分钟数、作者协助分钟数和第一个有用结果；不能独立完成的步骤记为阻碍，不隐瞒人工服务。

## 3. 每周反馈模板

### 团队记录（每团队复制一份）

| 字段 | 填写内容 |
|------|----------|
| 团队 ID / 是否关联 | 待记录；不要写私有仓敏感路径 |
| 接入日期 / 截止日期 / 观察天数 | 待记录；满 28 天才纳入四周留存 |
| 版本 / 语言 / A 或 B 组 | 待记录；A=已有自动化，B=仅人工 review |
| 是否继续启用 / 是否使用报告 | 待客户确认；定时任务自己运行不等于留存 |
| 接入 / 支持 / review 耗时 | 分钟；分别记录，比较同一 PR |
| 本周发现 / 决策 / 修复 | 脱敏证据或经许可的链接 |
| 不再使用的原因 | 噪声、无增量价值、接入成本、价格等，保留原话 |

### Finding 明细

| 匿名 PR / finding ID | 规则与事实证据 | 客户主分类 | 现有工具是否已报 | 行动与结果 | 评估人/日期 |
|----------------------|----------------|------------|------------------|------------|-------------|
| 待记录 | 待记录 | 待确认 | 未核实 | 待记录 | 待记录 |

四分类：**正确且有行动价值 / 事实错误 / 正确但预期如此 / 重复无行动价值**。未评估项保留为待确认。正确不代表独有价值；有用但现有工具已报也应如实记录。

抽查 N 个真实变更，经人工确认 M 个产品承诺范围内的问题，AV 漏报 K 个；只有 M > 0 才计算 K/M。写“本次抽查未观察到漏报”，不声称零漏报能力。误报率用已评估 finding 作分母，同时记录总 finding 和评估覆盖率。

### 付费与成本

| 团队 ID | 试用起止/优惠 | 首付日期/实际到账 | 购买原因 | 到期/续费日期及到账 | 支持分钟/托管成本 |
|---------|---------------|------------------|----------|---------------------|------------------|
| 待记录 | 待记录 | 未核实 | 产品价值/支持作者/咨询须区分 | 未到期不算未续费 | 待记录 |

只有实际到账、非关联团队因产品价值购买才计入核心付费阶段门。免费延长、沙箱订单、承诺付款、咨询交付收入单列。Team 人工申请不是完成购买。

## 4. 退出与决策

- 客户可随时停用；本地优先 `arch-viewer uninstall .`（可加 `--npm`），默认保留分层规则与证据；仅客户确认后才用 `--purge` 清会话报告/快照。
- 托管取消 webhook、撤销专用 PAT，并按部署方的数据保留流程处理账号/仓库信息。
- 10-09 检查使用证据及观察时长；11-06 按既定阶段门决策。不因日期到了就把晚接入团队填成四周留存。
- 没达到阶段门时停止订阅能力扩张，按计划转服务化验证；不继续堆语言、SSO 或仪表盘来替代客户证据。
