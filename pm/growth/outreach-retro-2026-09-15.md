## 2. 根因排序（从重到轻）

### 🔴 根因 1：首次触达直接要 15 分钟日历 — Ask Too Heavy

**问题：**
- 所有 A1–A6 私信都在第一段引子后立即提"想先约 15 分钟"
- B1–B3 英文同样结尾"Would you have 15 minutes"或"15 minutes to compare notes"
- 对陌生人来说，15 分钟同步会议是最重的承诺，需要：
  - 查日历、协调时区
  - 给陌生项目留出完整时间块
  - 承受"拒绝很麻烦、答应更麻烦"的心理成本

**证据：**
- outreach-kit.md §1 所有变体（A/B/C）都把"约 15 分钟"作为首次消息的 CTA
- 即使引子精准（AI 破坏架构、局部正确全局失控），第二段就要日历时间

**影响权重：极高（90%）— 单一最大障碍。**

---

### 🟠 根因 2：CTA 漏斗反向设计 — Wrong Ladder

**问题：**
- 传统销售漏斗：认知 → 兴趣 → 评估 → 承诺，每级摩擦递增
- 本次实际：引子（兴趣）→ 立即承诺 15 分钟（最重）→ 可能试用（次重）
- 跳过所有低摩擦中间态：
  - 没给"一句话回复确认痛点"的台阶
  - 没给"看一眼 npx 示例"的零承诺选项
  - 没给"点赞收藏回头看"的缓冲

**证据：**
- 软评阶段（09-12/13）的轻互动（点赞、「秀儿~」）证明有注意力
- 但私信升级到"约会议"后全部沉默

**影响权重：高（70%）— CTA 设计问题，不止是用词。**

---

### 🟡 根因 3：Gitee 招募跳出用户原生路径 — Gitee Friction for GitHub

**问题：**
- A1–A6（掘金）和 B1–B3（GitHub）的 CTA 终点都是 Gitee issue IKF74T
- 跳出用户当前平台：
  - 掘金用户 → 跳 Gitee（需注册或登录）
  - GitHub 用户 → 跳 Gitee（平台切换 + 语言切换）
- 增加一轮"我为什么要去另一个网站"的决策成本

**证据：**
- B1–B3 英文消息要求跳到**中文主导的 Gitee issue**
- A1–A6 要求从私信讨论区跳到公开 issue 报名

**影响权重：中（50%）— 非决定性，但叠加其他摩擦后成为弃坑点。**

---

### 🟡 根因 4：先软评论后私信 — Cold DM After Soft Comment

**问题（仅限 A1–A6）：**
- 09-12/13 已在文章评论区留过软评（"局部正确、全局失控这个说法太准了"）
- 09-14 再发私信要约 15 分钟
- 对方可能感受到："这人上次夸完就是为了这次推销"

**证据：**
- A1 有一条轻互动「秀儿~」，但私信后沉默
- 其余 A2–A6 软评无响应，私信同样无响应

**影响权重：中低（30%）— 两步法本身无错，错在第二步太重。**

---

### 🟢 根因 5：GitHub 新开 issue 而非回复已有讨论 — Opened Issue on Others' Repos

**问题（仅限 B1/B3）：**
- B1（Graphenium）和 B3（archcodex）是在别人维护的仓库里**新开招募 issue**
- 维护者可能视为：
  - 不请自来的招募帖（类似广告）
  - 与项目本身无关的噪音
- 社区礼节：优先回复现有讨论/issue，慎开新招募帖

**证据：**
- B1: https://github.com/lambda-alpha-labs/Graphenium/issues/39
- B3: https://github.com/ArchCodexOrg/archcodex/discussions/32
- B2（Yggdrasil）是 discussion 回复，相对礼貌但同样要 15 分钟

**影响权重：低（20%）— B2 用了 discussion 也无响应;核心还是 CTA 太重。**

---

### 🟢 根因 6：消息信息密度过高 — Message Overload

**问题：**
- 每条 A1–A6 私信 3–4 段，150–200 字
- 包含：引子 + 工具简介 + 试点说明 + 约 15 分钟 + Gitee 链接 + 版本号
- 初次私信读者在 3 秒内判断"要不要回"，信息量超过决策阈值

**证据：**
- 对比软评（09-12/13，1 句话共鸣引子）有轻互动
- 私信（3 段完整推介）零响应

**影响权重：低（15%）— 叠加因素，非主因。**

---

### 🟢 根因 7：样本量小 + 时间窗短 — Sample Size / Time

**客观限制：**
- 仅 9 条消息（6 中文 + 3 英文）
- 仅过 1 个工作日（09-14 晚发出 → 09-15 晨）
- 掘金私信可能被折叠或晚查看

**判断：** 不能完全排除"再等 2 天有回复"的可能性，但其他根因（Ask Too Heavy）已足够解释现象。

**影响权重：极低（5%）— 等待不改变 CTA 结构问题。**

---

### 🟢 根因 8：单向推送无价值前置 — Outbound-Only

**问题：**
- 所有消息都是"我想了解你 → 我有工具 → 约时间"
- 缺少"我先给你一个零成本的东西"：
  - 未附 npx 一行命令直接体验
  - 未附脱敏红绿样例图（虽然 kit 里有，但消息未带）
  - 未先回答对方可能的问题（"你们现在合入前靠什么确认跨层"仅作为访谈提问，未给答案）

**证据：**
- B1–B3 英文提"Happy to share our pilot data (46% initial FP rate)"但未实际附上
- 所有消息都以"你给我时间"结尾，非"我给你东西，你回头看"

**影响权重：低（10%）— 若 CTA 轻（如一句话问答），无前置价值仍可互动;但叠加 CTA 重时加剧放弃。**

## 3. 行动决策：停止 / 开始 / 继续

### ❌ 立即停止

1. **首次触达要 15 分钟会议** — 全面停用。访谈仅在对方主动回复后、第二或第三轮再提。
2. **首次触达跳转到 Gitee issue 报名** — 停用单一 Gitee 入口。改为"回复本消息"或"GitHub 自有仓库 discussion"作为首选 CTA,Gitee 仅作国内用户备选。
3. **在第三方 GitHub 仓库新开招募 issue** — 禁止。改为回复现有 issue/discussion,或仅在自有仓库 tomyangod/architecture_viewer 开放报名讨论区。
4. **3–4 段完整推介私信** — 精简到 2 段:1 句引子 + 1 个轻问 + 可选一行 npx 或样例链接。

### ✅ 立即开始

1. **首次 CTA 改为一句话可回复问题** — 例子：
   - 「你们现在合入前靠什么确认没跨层？」（可回复"人工" / "没管" / "dependency-cruiser"）
   - 「这类问题你们多久遇到一次?」
   - 答得上 = 痛点真实;答不上 = 非目标用户,双方都省时间。

2. **首次消息附零承诺礼物** — 例子：
   - `npx --yes arch-viewer@0.12.2-rc.5 session report .` 一行命令,无需安装
   - 脱敏红绿样例图直接贴在消息里（非链接）
   - 「我整理了三种常见拦截方案的对比,回复要的话发你」

3. **Day-3 跟进不再要日历，给软价值** — 例子：
   - 「理解可能不是当前优先级。如果你们最近合入过 AI 大改的 PR,我可以提供一行 npx 命令让你在本地跑一次演示（npx --yes --package arch-viewer@0.12.2-rc.6 arch-viewer session report <仓库路径>）。公开仓库我也可以直接跑,看红绿灯准不准。」
   - 「刚写了一篇对比文章（dependency-cruiser vs Import Linter vs Architecture Viewer 的定位差异）,要的话发你。」
   - 允许「暂不需要」明确退出。

4. **在 tomyangod/architecture_viewer 开设公开报名 discussion** — 作为 GitHub 用户的原生 CTA 终点,避免跳 Gitee。

### ↔️ 继续保持

1. **软评论策略（公开价值认同，不推销）** — 一条「秀儿~」证明有注意力,继续在掘金 / 知乎公开讨论区留软评,但**软评与私信至少间隔 3 天**,避免"先夸后卖"感。

2. **精准引子（引用对方具体痛点）** — A1–A6 的引子（"局部正确、全局失控" / "Prompt 里写 MUST NOT 仍擅自分层"）有共鸣,继续保持,只是后续 CTA 要轻。

3. **访谈话术（先问事实不评价）** — outreach-kit §2 的 6 个问题结构好,保留,但仅在对方回复初次消息后使用。

4. **试点纪律（拒绝即止、不催促）** — 继续坚持;零回复不是拒绝（是未读或沉默成本过高）,调整 CTA 后重试。

## 4. 新漏斗设计（四级 CTA 阶梯）

| 级别 | 用户承诺 | 我方给予 | 摩擦 | 转化目标 | 例子 |
|---|---|---|---|---|---|
| L1 首次软互动 | **读 30 秒 + 回复一句话** | 精准引子 + 一个轻问 | 极低 | 确认痛点真实 | "你们现在合入前靠什么确认没跨层?" |
| L2 零承诺礼物 | **回复要 / 点链接** | npx 一行命令 / 样例图 / 对比文章 | 低 | 让对方体验价值 | "要的话发你 npx 一行命令,3 秒跑完" |
| L3 真实场景试用 | **发一个 diff / 允许我跑一次** | 针对对方代码的红绿灯演示 | 中 | 证明对他有用 | "你们上周的 PR #123 我可以跑一次看准不准" |
| L4 访谈与试点 | **15 分钟会议 + 两周试用** | 专人陪同接入 + 每周反馈会 | 高 | 深度验证与案例 | outreach-kit §2 访谈 + §4 试点 |

**核心原则：**
- 绝不跳级:未完成 L1 不提 L2,未完成 L3 不提 L4。
- 每级给出路:允许"暂不需要"明确退出,避免已读不回的尴尬沉默。
- 礼物在前,索取在后:L2 先给 npx 命令或样例,对方用了再问"有用吗?";非先问"能给我 15 分钟吗?"。

## 5. 要观察的指标（下一批次起）

| 指标 | 09-14 基线 | 目标（09-17+ 批次） | 判断标准 |
|---|---|---|---|
| **首次回复率** | 0/9 = 0% | ≥ 20% | 哪怕回复「人工 review」或「没遇到」也算成功,证明 CTA 可行动 |
| **软→DM 转化** | 掘金 1 软评轻互动 → 6 私信 0 回复 | 软评 3 天后再私信,私信回复率 ≥ 10% | 避免"先夸后卖"反感 |
| **Gitee vs GitHub 讨论 CTA 差异** | Gitee IKF74T = 0 | GitHub discussion 回复数 vs Gitee issue 评论数 | 验证平台摩擦假设 |
| **Day-3 跟进礼物型 CTA 回复率** | 未测试 | ≥ 15% | "给你样例"或"跑一次演示"的回复率 vs 旧版"还感兴趣吗"基线 0% |
| **L1→L2→L3 转化率** | 未分级 | L1→L2 ≥ 30%, L2→L3 ≥ 20% | 验证阶梯是否通畅,哪级卡住 |

**判断周期：** 每批次（15–20 条消息）结束后 5 个工作日复盘一次,不超过 3 轮调整即需根本性转向（如放弃冷触达,改投社区内容 / 付费广告）。

---

## 6. 总结：一句话教训

**09-14 批次失败的本质不是引子不精准、不是渠道不对、不是样本量小——是我们在第一次见面就问对方要 15 分钟,相当于约会 app 第一句话就说"周五见个面吧"。**

解决方案:首次只要一句话回复,礼物和价值在前,日历在最后。
