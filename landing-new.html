Apache-2.0 · 零配置 · 不依赖 LLM · Node ≥ 18

AI 写完代码后，
自动看清架构变了什么

AI 编码会话一次改动几十个文件，合入前没人说得清架构到底变了什么。 Architecture Viewer 用会话基线 → 变更图谱 → 影响面分析，把答案摆在你面前： IDE 状态栏、PR 评论、CLI 三端可用。

立即开始（30 秒） 查看源码 →
$ npx arch-viewer session start  # 让 AI 改代码前记录基线 $ npx arch-viewer session report  # 会话结束看 Before/After
STAGE 01 — 会话验收门

AI 会话收尾，一条命令过架构门

让 AI 动手前先 session start 记录架构基线；会话结束 session report： 实体增删改、外部依赖变化、风险分级、反向依赖影响面一次看清，高风险退出码为 1—— 可以直接卡进 Cursor / TRAE / Copilot 的工作流规则。

STAGE 02 — PR 自动评论

每个 PR，自动贴一张架构影响面

复制一份 GitHub Actions 工作流即可。PR 打开或更新时自动对比 base 与 head 的代码图谱， 把变更计数、第三方依赖清单、风险发现和影响面贴成评论。同一 PR 重复 push 只更新原评论，不刷屏。

STAGE 03 — 影响面分析

反向依赖 BFS：这次改动会波及谁

从被改实体出发，沿 import / extends / implements / calls 等连线反向追踪， base 与 head 双向边取并集、穿透被改实体集群，报告集群边界之外的直接与间接受害者。 归属关系边自动折叠，红灯只亮在刀刃上。
