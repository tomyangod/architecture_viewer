一条引擎，两个入口

扫描、生成、校验全在 lib/ 里，Web 和 CLI 共用一套引擎。 Web 负责粘贴 URL 即出图；CLI 负责写进仓库 + CI 漂移红灯。

① 网页版 · 粘贴即出图

粘贴 Git 仓库 URL，得到六视图分享页 /p/<id>。无 Key 即时骨架；有 Key 精修后再分享。

  • 支持 GitHub / Gitee / GitLab 公开仓库
  • 可缩放、搜索节点、高亮依赖
  • 一张链接发评审会，图随版本走

② CLI · 写进仓库 + CI 漂移

npm i -g arch-viewer。Init → Generate → check --drift。图落在仓库里，跟 PR 一起 review。

  • 六视图一次出图，图随仓库保存

  • 零运行时依赖，Node ≥ 18 即可

为什么别再手画架构图

大多数架构图的半衰期就是发出去那天的下午。人走、代码动、需求改，图就开始撒谎。 我们的解法不是让你"更勤奋"，而是让代码 自己告诉图该怎么变。

痛点

  • 写完一次就没人维护
  • 新人入职看的是"去年的真相"
  • 评审会上对不上模块名
  • 运维部署跟图上的架构不一致

Architecture Viewer

  • Generate 一键更新六视图
  • PR 里自动跑 Validate，漂移直接红
  • 节点 ID 对齐到真实模块 / 服务名
  • 部署目录、compose 服务、入口文件都纳入扫描

Coffee Shop · 咖啡订单平台

故意坏图 · 这才是付费理由

安装 · 一分钟跑起来

Community 永远免费 + 开源（Apache-2.0）。两种方式任选其一。

CLI

命令行 · 给 CI 与脚本用

一条命令 Init + Generate，CI 里跑 Validate 做门禁。

  • Node ≥ 18，零运行时依赖
  • 跟网页共用同一套 lib/ 引擎
  • GitHub Actions 模板：PR 漂移红灯
  • 可选 LLM 精修（用户自带 API Key）
看 README 
npm i -g arch-viewer
arch-viewer init ./your-repo
arch-viewer generate ./your-repo
# 精修（需 DEEPSEEK_API_KEY）：
arch-viewer generate ./your-repo --refine
arch-viewer check ./your-repo --drift
Docker

自托管 Web · 给团队用

一条 docker compose up，团队共享 Web 入口。

  • 粘贴 Git URL → 骨架即时 / 精修约 30–90 秒 → 分享链接
  • 数据持久化（.data/ 卷）
  • 内网部署，代码不出局域网
看 Dockerfile 
git clone https://gitee.com/heyangyan/architecture_viewer.git
cd architecture_viewer
docker compose up -d
# 打开 http://localhost:3847
